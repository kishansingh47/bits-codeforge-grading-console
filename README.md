# BITS Digital CodeForge V1.0 — Submission

Prototype grading console: [`BITS_Digital_CodeForge_Challenge.html`](BITS_Digital_CodeForge_Challenge.html). No build step — it's a single static HTML file that runs entirely in the browser (marks parsing is done client-side with SheetJS).

## Stage 1 — Bug Fix Log

All bugs below were found by exploring the app in a browser and reproduced/verified by directly exercising the app's own functions in the DevTools console (feeding it real and synthetic `.xlsx` data), not just by reading the code.

| # | Bug / Issue Identified | How You Reproduced It | Root Cause | Fix Implemented | How You Tested the Fix |
|---|---|---|---|---|---|
| 1 | Course dropdown fills with duplicate entries — even on the **very first** upload, not just a second one | Uploaded a file where one course had multiple students (e.g. "Course A" with 8 rows) | `file.onchange` added one `<option>` per **row**, with no de-duplication, and never cleared old options before a re-upload | Cleared all options back to the placeholder on every upload, then added one option per **unique** course name via `[...new Set(...)]` | Uploaded a file with 8 rows under "Course A" + 3 under "Course B" → dropdown showed exactly `["", "Course A", "Course B"]`. Re-uploaded a second file → old options were gone, replaced only by the new file's courses |
| 2 | Selecting a course with no matching rows shows `NaN` / blank stats instead of a sensible empty state | Programmatically selected a stale course value that had 0 rows in the current dataset (realistic after bug #1/#3, e.g. right after uploading a new file while an old course was still selected) | `computeStats()` divided by `m.length` and indexed `m[0]`/`m[m.length-1]` without checking `m.length === 0` | Added an explicit empty-state guard that shows `"–"` for Max/Min/Avg/Median instead of computing on an empty array | Selected a course with zero matching rows → all four stat boxes cleanly showed `"–"` instead of `NaN`/`undefined` |
| 3 | The "Min" stat box actually shows the **maximum** mark, and the "Max" box shows the **minimum** | Uploaded marks for a course and compared the displayed Min/Max against the actual data (e.g. marks 10–82 → box labeled "Min" showed 82) | The stat `<div>`s and the `id="min"`/`id="max"` elements inside them were swapped in the HTML, while `computeStats()` correctly wrote the true min to `#min` and true max to `#max` | Re-ordered/re-paired the stat boxes so the "Max" label wraps `#max` and "Min" wraps `#min` | Re-tested with marks 10–82 → "Max" box now shows 82, "Min" box shows 10, matching the raw data |
| 4 | The file picker only accepts `.xls`, blocking selection of the `.xlsx` files the app actually requires and parses | Inspected the file input; on Windows, `accept=".xls"` filters the native file dialog so `.xlsx` files can't even be selected | `accept` attribute on `<input type="file">` was set to the wrong extension | Changed `accept=".xls"` to `accept=".xlsx"` | Uploaded a real `.xlsx` file end-to-end (via a programmatic `DataTransfer`/`change` event) and confirmed it parses and populates the course list correctly |
| 5 | "Reset Range" pops up **two** identical confirmation dialogs in a row for one click | Clicked "Reset Range" | `resetRanges.onclick` called `confirm(...)` twice back-to-back with near-identical text | Removed the redundant second `confirm(...)` call | Clicked "Reset Range" → exactly one confirmation dialog appears before ranges reset |
| 6 | Timer display sits frozen for a full second after page load instead of reflecting elapsed time immediately | Reloaded the page and inspected the timer text/arc right after load | `startTimer()` only updated the clock text/arc **inside** `setInterval(...)`, so nothing rendered until the first 1000ms tick fired | Extracted the update logic into `tickTimer()` and called it once immediately in `startTimer()` before starting the `setInterval` | Reloaded the page and read `timerText.innerText` immediately (no wait) → showed the correct live elapsed time instead of a static placeholder |
| 7 | Grade-count badges (A/A-/B/…) "pulse" as if a range changed, purely from switching courses | Selected Course A, then switched to Course B (different mark distribution) without touching any range | `previousSummary` (used to detect a real change and trigger the pulse animation) was never reset when a new course was selected, so a different course's counts were compared against the old course's counts | Reset `previousSummary = {}` whenever a course is (re)selected, so the pulse only fires for changes made *while viewing the same course* | Selected Course A (captured badge counts), switched to Course B, and confirmed the counts differed only because of the course switch — with the fix, no spurious pulse state carries over |

## Stage 2 — Enhancements

Chosen deliberately to solve gaps a real instructor would hit, not to add surface-level polish. The core upload → select course → configure ranges → download flow is unchanged.

1. **Student-wise Results table (search + sort)** — Previously the app only showed aggregate stats and grade *counts*; an instructor had no way to see which grade an individual student actually got until after downloading the CSV. Added a live, searchable (by BITS ID), sortable (click any column) table of every student's marks and assigned grade, so the instructor can verify correctness *before* finalizing.
2. **Upload data validation** — The file-format guidance text promised things the app never enforced (whole-number marks, 0–100 range). Rows with a missing BITS ID/Course or an out-of-range/non-numeric mark are now dropped and reported; fractional marks are rounded per the stated guidance; duplicate BITS IDs within a course are flagged. A small warnings banner explains exactly what happened instead of the app silently mis-grading on bad data.
3. **Confirm-before-discard on re-upload** — Uploading a new file resets the whole workspace (a necessary fix alongside bug #1). If an instructor has already selected a course and started reviewing ranges, choosing a new file now asks for confirmation first, so in-progress work isn't wiped by an accidental re-upload.
4. **Accessibility & responsiveness pass** — Added accessible names (`aria-label`) for the instructor/file/course controls, `aria-live`/`role="alert"` regions so screen readers announce the welcome message, validation errors, upload warnings and the finalize confirmation as they appear, `aria-sort` on the new table's sortable headers, and a responsive breakpoint (`max-width: 760px`) that stacks the two-column layout into one column instead of overflowing on narrow/mobile screens.

Small related cleanups made along the way: consolidated the "which grade band does this mark fall into" logic (previously duplicated three times — grade-summary counts, CSV export, and now the results table) into a single `gradeFor()` helper, and fixed a stray-space inconsistency in the exported CSV header.
